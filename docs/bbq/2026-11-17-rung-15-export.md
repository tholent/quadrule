## Defaulted (the lead's calls; each can be vetoed)

- **Tokens.** `{title}` the document's title, else the file's name, else `untitled` (`sample` for the sample page);
  `{device}` the profile's short name (`manta`, `nomad`, a paper size's short name); **`{profile}` kept as the spec's
  name for the same value**; `{model}` the profile's display name, slugged (there is no model field); `{width}`,
  `{height}` the PNG's size (the device's portrait size, for a landscape design too); `{orientation}` `portrait` or
  `landscape` (the design's); `{type}` `template` or `wallpaper`; `{date}` the export day, `YYYY-MM-DD`, local time;
  `{version}` the app's version with dots as hyphens (`0-15-0`); `{set}` the Set box. veto: `{device}` replaces
  `{profile}` outright; `{version}` means something else.
- **Safe names.** Each token's value is slugged; literal text in the template keeps only letters, digits, `-`, `_` and
  `/`, and anything else becomes a hyphen. `.png` is added if the path does not end in it. A part left empty is dropped.
  veto: none expected.
- **Mistakes block Export.** An unknown token, or two devices landing on the same path (All devices with no
  `{device}`-like token), shows in red in the preview and greys out Export. veto: add the device name by itself.
- **Existing files are replaced** without asking; the completion sheet says how many were replaced. veto: ask first.
- **Preflight.** Export on the sheet closes it and, when 14b's rules call for it, opens the one "Before you export"
  sheet for the chosen devices; Export anyway writes. Export again passes through the same preflight sheet. Never two
  sheets stacked (rung 15 prompt). veto: none expected.
- **Settings file.** One `settings.ron` in the app's config folder (`XDG_CONFIG_HOME/quadrule` on Linux) holds the
  template, the set, the note tick, the devices choice, the folder map, the last folder and the fold state. A damaged
  file gives the defaults and a notice; the folder map keeps the 200 most recent documents. veto: none expected.
- **The very first folder** (nothing remembered yet) is the document's own folder if it has been saved, else the home
  folder. veto: the Pictures folder.
- **Export again** with nothing exported yet from this document (this session or remembered) opens the sheet instead.
  Shortcuts Ctrl+E and Ctrl+Shift+E (Cmd on macOS), unless they clash with a shortcut the app already has, in which
  case the builder says so. veto: other keys.
- **Text note encoding.** Latin-1 text goes in `tEXt` chunks; a title with other characters goes in an `iTXt` (UTF-8)
  chunk. With no title, the Title chunk carries the file's name or is left out (builder's call, said at the look).
  veto: none expected.
- **Completion thumbnails** are shrunk from the pixels just written, not read back from disk. **Reveal in folder** opens
  the export folder (the deepest folder all files share) in the system's file manager; failure gives a notice. veto:
  none expected.

## Amendments

- **2026-11-17, during leg 1: EXIF or XMP for the note?** chris asked whether a standard EXIF/IPTC tag would be better
  for the program version than a text chunk. The lead showed that Software and Title are the PNG format's own
  predefined text keywords (W3C PNG third edition, §11.3.3.1; read from a summary of the page, not quoted), that EXIF
  in PNG is the later `eXIf` chunk (§11.3.4.5) with patchier support, that IPTC has no PNG chunk of its own, and that
  XMP (an `iTXt` chunk keyed `XML:com.adobe.xmp`) is the cross-format route; all are ancillary chunks a decoder may
  skip. chris, word for word: **"I agree, keeping the software and title fields is the right call"**. Q6 stands as
  written; XMP is not built (a possible v1.1 addition, not owed).
